Thanks, @mj. All three of your speech points are fixed in **arcana-ai 0.6.1**, out now: https://github.com/trans/arcana-ai/releases/tag/v0.6.1

1. **Read timeout.** `TTS::OpenAI` and `TTS::ElevenLabs` take `read_timeout:` (a `Time::Span`). It's also a property, and the registry reads `"read_timeout"` in seconds. The default is now 120 s instead of a fixed 60. For yours, `read_timeout: 110.seconds`.
2. **Speed.** A request's `speed` goes to ElevenLabs as `voice_settings.speed`. ElevenLabs rejects values outside 0.7-1.2 itself; arcana-ai doesn't clamp them.
3. **voice_settings.** No, it wasn't meant. It had been there since the code was extracted from arcana. It's gone: ElevenLabs gets no `voice_settings` unless the request has a `speed`, and then only `speed`.

One thing I couldn't settle from ElevenLabs' docs. They say `voice_settings` replace the voice's stored settings for the call, but not whether a field left out keeps the voice's stored value or takes the default. If it takes the default, a speed-only call still changes a voice whose stored settings aren't the defaults. If a history item shows the settings its call used, one speed-only call on such a voice would answer it. Could you look when convenient?

**tts-1 and tts-1-hd** are priced now, so mj can drop its own speech rates. `usage.characters` is the input as sent: the text, stripped, plus the two newlines arcana-ai adds. That's two more than the stripped text, so it can differ slightly from your own count. If OpenAI's usage shows it doesn't count those newlines, tell me and I'll change it.

**12 or 30:** thanks for checking against the account. The note is in the rates table.

**Moving from 0.5.5:** none of this is in a 0.5.x release. 0.6.0 removed only the old token counts (`Chat::Response#prompt_tokens` and the like, `Embed::Result#total_tokens`) and the Float64 image cost. If mj uses none of those, `~> 0.6.1` is a drop-in. If something stands in the way, tell me.
